Fbeore handeling data to the service layer
we have to make sure that data is in the correct format

when validation errors arrive to the repository database level you can only return error 500 internal server error which is poor user experience. So we validate at the handler level.


return data in this form (or like it but keep it in mind)
```
{
  "errors": [
    {
      "path": "/x/y",
      "message": "incorrect blabla"
    },
    {
      "path": "/x/z",
      "message": "incorrect wayaya"
    }
  ]
}
```
# syntactic
wether an email is an email or not (format validation)


# symantic validation

when the form is correct but data dosen't make sense
for example a date with this form 2026-08-123 is 100% wrong.

# Type validation
that a name is actually a string for example etc etc.

# Transformation

casting parameters etc etc into validatable types.
for example transforming the limit query parameter from string to int.

# Frontend validation vs Backend validation

frontend validation is for UX while backend validation is for data-integrity and security.
